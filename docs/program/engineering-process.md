# Engineering Process

Project Meadowlark is developed using a systems engineering approach. Every feature, subsystem, and design decision should be driven by documented requirements, validated through testing, and captured in project documentation.

The engineering process is intended to produce a project that is understandable, reproducible, maintainable, and extensible by others.

Engineering takes precedence over implementation speed.
The goal of Project Meadowlark is not only to build autonomous aircraft, but also to demonstrate a disciplined engineering process that others can study, reproduce, and improve.

---

# Guiding Philosophy

The guiding principle of Project Meadowlark is:

> Engineering over everything.

This means that:

- Requirements are defined before implementation.
- Major design decisions are documented.
- Testing validates engineering decisions.
- Documentation is treated as part of the deliverable.
- Designs should be reproducible by others.
- Simplicity is preferred over unnecessary complexity.

---

# Engineering Lifecycle

Development generally follows this sequence:

1. Identify the problem.
2. Define requirements.
3. Evaluate candidate solutions.
4. Document the selected approach.
5. Implement.
6. Test and validate.
7. Record lessons learned.
8. Refine and iterate.

Not every task requires every step, but every significant subsystem should follow this general lifecycle.

---

# Decision Making

Engineering decisions should be based on:

- documented requirements
- technical evidence
- testing
- maintainability
- affordability
- reproducibility

Personal preference should not outweigh engineering evidence.
